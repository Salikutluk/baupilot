## 1. Goal and scope

**Goal (M7-ios.md):** all 68 iOS snapshots and all iOS click paths green; the iOS app is accessible.

**In scope (the five M7 tasks, iOS only, in this plan's order):**

1. **Links:** an XCUITest for every link with a target listed in the "Links" sections of M2–M6 (100 screen→target pairs over 34 screens, counted by parsing the `- Links:` lines; iOS and Android lists are identical), plus a "does nothing" test for every placeholder (`href="#"`, `null` route).
2. **VoiceOver:** labels from `aria-label`; the diagrams Zeitplan, Gefälle and Raster each one element with a description; the iOS semantics gaps found in research (§2.3) fixed.
3. **Touch targets:** an automated check over all 34 screens (≥ 44 pt).
4. **Diff report:** one machine-made report over 34 screens × 2 modes (68 iOS rows), a fresh baseline, honest attempts at the remaining residue, and a justification per row that stays red.
5. **Large text:** renders at Dynamic Type xL for all 34 screens, an automated overlap/clipping check, fixes, and a recorded visual review.

**Acceptance (M7-ios.md)** — mapped in §10: 68/68 iOS snapshots green; all iOS UI tests green; iOS accessibility audit without errors.

**Out of scope:** everything under `android/`; real data and persistence (M8); new screens; any change to `design/`, `fixtures/`, references, tolerances or tokens in `design/tokens.json`; new visible text. Placeholder links stay placeholders.

**Honest expectation, stated up front (see §8 R1):** research shows the iOS snapshots top out at about 0.985 on screens whose layout is proven exact (Login, EsEbenheit, MaUebersicht), below the required 0.995. Glyph rasterization (CoreText vs. Chrome/Skia) is the cause. The plan makes real attempts to close it (Steps 12–13), but AC1 likely stays unmet. That outcome is **reported per snapshot with evidence, never hidden**. Tolerances are not loosened, and references are not re-recorded.

## 5. Contracts

### 5.0 Shared files (both platform plans touch them)

- **`scripts/`:** only additive, backwards-compatible changes. If the Android plan already added a module or option this plan needs, reuse it; never change its behaviour. `cd scripts && node --test test/` is green at the end of every step.
- **`scripts/link-coverage.json`:** gets a top-level `"platforms": { "ios": <bool>, "android": <bool> }`. A platform's mappings are validated only when its flag is `true`. This plan sets `"ios": true` at the start of Step 5 and never touches `"android"` or any `android` field (a missing `android` field is allowed while `"android": false`).
- **Gallery goldens, references, `design/`:** unchanged unless D17/D18 allow (iOS goldens only).

### 5.2 Harness result sidecar (Step 2)

The sidecar is the only way the test verdict and value reach the report. **Only screen snapshots write one**; gallery goldens and the canary do not (I13).

- `ReferenceSnapshot.assertMatches` writes `<artifactDir>/<Name>_<mode>.result.json` after `diffV2` and before the attachments/`XCTFail`, only when the pure predicate `ReferenceSnapshot.writesSidecar(artifactDirectory:writeArtifact:)` holds (`artifactDirectory == "ios" && writeArtifact`). `passed` = `diffV2` returned nil. The `XCTFail` call and its message stay unchanged. When `render` throws (timeout, `checkSize`), neither PNG nor sidecar exists; `--all` reports the row as `missing-actual`.
- **Shape:**
  ```json
  { "platform": "ios", "name": "SanGefaelle", "mode": "light"|"dark",
    "passed": true|false, "message": "<verbatim failure message or empty>",
    "value": <number|null>, "required": <number>, "unit": "precision" }
  ```
- **`value`:** pure function `ReferenceSnapshot.result(passed:message:)`: `/pixels that match ([0-9.]+) is less than required/` (the pixel-match ratio vs. 0.995; a regex on `precision … is less than required` would capture the *perceptual* line instead). Null on pass, on a size-mismatch message, or on no match. **The parse never changes the verdict.**
- **`required`:** read from the harness constant `precision`, never a new literal.
- **T-DS-3 naming trap:** Swift test code outside `ReferenceSnapshot.swift` must not use a `precision:` or `perceptualPrecision:` label. The Swift result type uses `pixelMatch:` / `required:`; the JSON key stays `value`.
- **Write failure:** throws `ReferenceSnapshotError.artifactWriteFailed` like the PNG. `--all` reports a missing sidecar as `missing-result`.
- **Tests (red-first):** new `ios/BaupilotTests/Snapshots/ReferenceSnapshotSidecarTests.swift`: `testSidecarParsesPixelMatchFromPerceptualMessage` (fixture: the two-line message of §2.1), `testSidecarOnPassHasNullValue`, `testSidecarSizeMismatchHasNullValue`, `testSidecarOnlyForScreenArtifacts` (on the predicate).

### 5.3 `scripts/diff-report` whole-run mode (Step 2)

New module (reuse if already on the branch; `feat/m7` has it):
- `scripts/lib/band-shift.mjs` exports `bandShift(refRGBA, actRGBA, w, h, { bandHeight, maxShift = 6 }) -> { positionShare, bandsImproved, bands: [{ y0, best, dev0, devBest }] }`. Per band, `dev(s)` is the mean absolute RGB deviation of `act` rows `y+s` against `ref` rows `y`; `best = argmin_s dev(s)` for s ∈ [−6, 6]; `positionShare = Σ(dev0 − devBest) / Σ dev0` (0 when Σ dev0 = 0); `bandsImproved` = bands with `devBest ≤ 0.8 · dev0`. `bandHeight` is 60 px for iOS (43 bands).
- `scripts/lib/offbytwo.mjs` (Android column) is only needed if `--all` runs without `--platform`; reuse it if present, otherwise leave the `offByTwoPercent` column null for iOS rows (it is Android-only by definition).

`scripts/diff-report.mjs` gains:
- **`--all [--platform ios|android]`:** the expected set is `parseScreens(design/screens.md)` × {light, dark} × the given platform (both when `--platform` is absent; this plan always passes `--platform ios`). Per row:
  ```json
  { "nr", "name", "platform", "mode", "status": "ok"|"missing-actual"|"missing-result"|"size-mismatch",
    "test": { "passed", "value", "required", "unit" } | null,
    "percentDifferent", "offByTwoPercent" (android only, else null),
    "positionShare", "bandsImproved", "actualSha256" }
  ```
  `actualSha256` is the SHA-256 (`node:crypto`) of the decoded actual RGBA. Status precedence: `missing-actual` > `size-mismatch` > `missing-result` > `ok`. The expected set comes from a `screens` option on `run()` (default `parseScreens` of `design/screens.md`, which takes the markdown text).
  Output: with `--platform p`, `reports/summary-<p>.json` (`{ generatedAt, rows: [...68], totals: { <p>: {green, red, missing} } }`) and `reports/summary-<p>.md`; without, `reports/summary.json`/`.md` over 136 rows. Table columns: Nr · Screen · Plattform · Modus · Test (✓/✗ + value) · Diff % · OffByTwo % · Lagenanteil · Bänder, ordered by `nr`, platform, mode. The per-platform panels and the existing `summary.json` are still written.
- **`--baseline <path>`** (only with `--all`): `changed: [{ name, platform, mode, field, before, after }]` for every row whose `actualSha256`, `test.passed`, `test.value`, `percentDifferent` or `offByTwoPercent` differs (`|a−b| > 1e-6`). Rows of a platform outside the current `--platform` are ignored.
- **`--unstable <path>`** (only with `--baseline`): rows listed in its `changed` are compared without `actualSha256`.
- **Exit codes:** existing unchanged (1 reference missing, 2 usage or `PngError`); **3** when an expected actual or sidecar is missing under `--all`; **4** when `--baseline` finds changes. Red tests alone do not change the exit code.
- **Usage errors (exit 2):** `--all` with `--name`/`--mode`/`--actual`; `--baseline` without `--all`; `--unstable` without `--baseline`; an unreadable baseline/unstable file. Each prints `diff-report: <reason>`.
